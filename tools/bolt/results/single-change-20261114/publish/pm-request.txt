Patch Set 1 - Part 1: hybrid LLVM linkage on x86_64

How to review: this change is uploaded as three cumulative patch sets.
PS1 contains Part 1. Compare PS1 -> PS2 to see Part 2 (BOLT) alone,
and PS2 -> PS3 to see Part 3 (flags and archive conversion) alone.

What Part 1 does:
- On x86_64, LLVM/Clang tools link against libLLVM and libclang-cpp,
  while clang, lld and llvm-ar stay statically linked (these are the
  binaries qemu-accel uses for cross builds).
- It is selected by TIZEN_HYBRID_LINK, which only the x86_64 recipe
  sets. Without it, the new CMake helpers return immediately and the
  upstream behavior is kept.
- Files: llvm/cmake/modules/AddLLVM.cmake,
  clang/cmake/modules/AddClang.cmake, lld/cmake/modules/AddLLD.cmake,
  the clang, lld and llvm-ar CMakeLists.txt, packaging/llvm.spec.

armv7l/aarch64: build behavior is unchanged. AddLLVM.cmake and
AddClang.cmake are installed on every architecture, so the ARM
llvm-devel and clang packages carry the new CMake text. Against the
pre-change QB builds (1216401/1216400), 60 of 68 ARM packages are
identical and the other 8 differ only in these two files.

Rollback: revert Part 1.

Validation: PS1 was not built on its own; it was validated as part of
the complete series (see the PS3 note).

<<<PS2
Patch Set 2 - adds Part 2: BOLT-optimized clang on x86_64

Compare PS1 -> PS2 to see Part 2 only. Files:
- packaging/clang-bolt-helper.py (new)
- packaging/clang-bolt-v2.fdata.xz (new, binary BOLT profile,
  9,735,212 bytes, SHA256 52fd8522...)
- packaging/llvm.spec

What it does (x86_64 only):
- After the normal build and install, clang is relinked with
  --emit-relocs, rewritten by BOLT with the prebuilt profile, stripped,
  and installed in place of the ordinary clang. lld and llvm-ar are
  not changed.
- The build fails if the profile does not match the clang being built
  (stale-profile ratio above 5%) or if any identity, safety or smoke
  check fails. There is no silent fallback to the ordinary clang.
- The profile was collected offline from 13 ARM and 10 AArch64 compile
  workloads (generated and real LLVM sources). No training runs inside
  the RPM build.
- The packaged clang is about 9% larger (152.5 MB vs 139.9 MB).

Speed (historical local measurement, 30 single-file LLVM C++ -O3
compiles): the BOLT clang needs about 0.856x the time of the ordinary
clang on x86_64, with similar results when compiling for ARM and
AArch64. A QB A/B measurement of the final build is still pending.

Build cost: about 32 minutes for the BOLT stage in a local full build
(about 19% of the total), measured on an earlier revision with the
same BOLT spec and helper.

armv7l/aarch64: unchanged. BOLT steps and BuildRequires are guarded
for x86_64; the two Source lines are unconditional so the Patch lines
generated by gbs stay visible on every architecture.

Rollback: change "bcond_without clang_bolt" to "bcond_with clang_bolt"
for x86_64 (one line). This disables BOLT only; Part 1 stays.

Validation: PS2 was not built on its own; see the PS3 note.

<<<PS3
Patch Set 3 - adds Part 3: fixed x86_64 flags and archive checks

Compare PS2 -> PS3 to see Part 3 only. Files: packaging/llvm.spec,
packaging/llvm-static-archives-native.py.

What it does:
- x86_64 compile and link flags are fixed to the Toolchain project's
  effective values, so a GCC-oriented project no longer passes options
  that clang rejects (-feliminate-unused-debug-types). Dropped and
  unreviewed project options are printed (TIZEN_LLVM_DROPPED_FLAGS,
  TIZEN_LLVM_FLAGS_WARNING) and do not stop the build.
- The static-archive converter from Change 359934 gets an explicit
  debug-info mode, a same-version check of its three tools, stricter
  archive/ELF/relocation parsing, and signal handling.

Validation of the complete series (this tree):
- QB 1226850 (Tizen-Base-Toolchain) and 1226851 (Tizen-Base-Dev):
  x86_64, armv7l and aarch64 builds all succeeded.
- All 102 binary packages have the same payload as the previous QB
  validation of these changes (1225393/1225395); 1294 static archives
  (22,520 members) are identical member by member.
- Local full builds of both projects match QB (Base-Dev byte-identical;
  Toolchain debug files differ only in the Release path prefix). The
  final clang is identical between local and QB builds, and LLDB
  resolves 21/21 clang frames with the installed debug info.

Known open items (tracked, not blocking):
1. QB A/B speed measurement of the final build is pending.
2. BOLT prints 10 "jump past end ... replacing with nop" warnings. The
   BOLT source treats this pattern as the result of
   __builtin_unreachable(): a branch to the very end of a function,
   taken only if an "unreachable" assumption is violated. 2 sites are
   traced to llvm_unreachable in the source; the other 8 show the same
   pattern; analysis continues.
3. BOLT reports "Failed to analyze 2804 relocations" (relocation types
   it does not support); a per-type census is in progress.
4. A defensive hardening patch for the converter will follow
   separately.
