Build BOLT from the standalone llvm-tools-subpkgs spec against the
installed LLVM packages on x86_64 and aarch64. That build links
libLLVM.so, while in-tree BOLT keeps linking the LLVM component
libraries; BOLT_LLVM_LINK_MODE selects the mode before its consumers.
The X86 helper mirror is compiled only for the standalone dylib build
and is listed in LLVM_OPTIONAL_SOURCES otherwise, and the inherited
runtime C and C++ flags are cleared only for standalone builds.

The standalone spec pins its LLVM provider build requirements to the
LLVM version and checks that the installed providers share one version
and release, sets BOLT_TARGETS_TO_BUILD per architecture and verifies
target registration, keeps the distribution LDFLAGS, derives
LLVM_LIBDIR_SUFFIX from %{_lib}, and installs merge-fdata through its
CMake rule. bolt requires libllvm = %{version} at runtime.

clang now ships scan-build, scan-build-py, analyze-build and
intercept-build with their libexec scripts, report resources, manual
page and Python modules; the modules are no longer deleted at install
time. The scan-view data moves from llvm-devel to llvm, next to
scan-view. Six installed scripts now use Python 3 shebangs, and
packaging checks the new first lines. No Python runtime requirement is
added. llvm and clang provide the llvm-xray, llvm-prof-tools and
clang-analyzer names and obsolete their older versions.

Later revisions withdrew armv7l BOLT packaging and the llvm python3
requirement described in the history above. When MLGO is enabled,
%build extracts the verify assets if their directory is absent,
including when %prep was skipped.

The standalone spec adds --build-id=sha1 to the executable and shared
library linker flags. The llvm spec adds it to those flags when
_toolchain is defined, as it always is on x86_64. Module linker flags
keep their existing settings.
