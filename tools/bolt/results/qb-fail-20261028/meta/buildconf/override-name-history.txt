    Tizen-Base-Toolchain: limit section GC to Clang builds
    
    Global --gc-sections also reaches packages that override the default
    Clang toolchain with GCC. This breaks glibc's libc_pic.os partial link:
    GNU ld requires an explicit root symbol when combining -r with section
    GC, but this intermediate object has no such root.
    
    Move --gc-sections into the Clang-specific linker flags and resolve the
    selected flags at macro expansion time so package-level toolchain
    overrides take effect. Preserve the common and architecture-specific
    linker flags.
    
    Validation:
    - Passed 18 RPM macro expansion checks across six architectures.
    - Completed an aarch64 glibc GBS build using the modified project config
      and the local gbs.conf; generated 15 binary RPMs.
    - Confirmed libc_pic.os links successfully without --gc-sections.
    - The glibc test suite remains skipped by the existing project config.

    Prepare Tizen-Base-Toolchain build root for libc++
    
    Two changes to TIZEN/Tizen/Tizen-Base-Toolchain/project_config:
    
    1. Remove the lld default linker (-fuse-ld=lld in build_ldflags). It
       has not passed validation yet, so the next build uses the GNU linker
       as before. It will be submitted again after validation. This reverts
       commit bae4ebdd732e3c01611de2414434d4c5c162763c.
    
    2. Add libc++ to the build root, to build C++ packages with LLVM libc++
       instead of libstdc++:
       - Support: add libc++-devel and libc++abi-devel, so that every build
         root can compile and link C++ code against libc++.
       - Keep: keep libc++, libc++abi and their -devel packages in the
         build root, in the same way as libstdc++ and libstdc++-devel.
    
    libstdc++ stays in the build root. Packages that do not select libc++
    keep building with libstdc++ as before, and GCC builds are not changed.
    Packages select libc++ in their own spec (build_with_libcxx under the
    clang toolchain).
    
    The libc++ packages are built from packaging/libcxx-runtimes.spec in
    platform/upstream/llvm. libcxx-runtimes is not in the current
    Tizen-Base-Toolchain repository, so the Support entries must only take
    effect after libcxx-runtimes has been built and its binaries are
    published; otherwise every package in the project becomes unresolvable.
