clang-accel collects more than clang, lld and llvm-ar. Its spec also selects clang-*, llvm-*, opt, lli, llc, libLTO and LLVMgold, and collects their shared-library dependencies with ldd. The files are placed under /emul; common files already supplied by qemu-accel are removed from the clang-accel file list.

Consequently, Part 1 still brings libLLVM.so.22.1 and libclang-cpp.so.22.1 into this set through tools such as opt and clang-scan-deps. Keeping clang, lld and llvm-ar statically linked to LLVM does not prevent that. The trade-off is that the other tools no longer carry separate copies of the LLVM components. Part 2 increases the selected clang executable from approximately 140 MB to 153 MB, about 9%; the clang aliases are restored as symlinks rather than separate copies.

I simulated the LLVM-supplied file set using the retained pre-hybrid static LLVM 22.1.8 RPMs and the RPMs from QB 1226850. Summing regular-file sizes by destination path gives 2,748,086,080 versus 624,565,496 bytes, a 77.27% reduction (106 versus 108 regular-file paths). Counting identical file contents only once gives 2,481,806,920 versus 492,543,704 bytes. These are file-set measurements before patchelf and final hard-link processing, not a measured final clang-accel RPM size; non-LLVM system libraries and filesystem metadata are excluded. The older published 22.1.8-1.6 RPMs are a different baseline: their clang is already dynamically linked, and their corresponding set is 238,611,928 bytes by path. That comparison must not be described as the effect of hybrid linking alone.

There is no measured before/after setup time for a rebuilt accel package yet. The saved Toolchain ARM logs still install clang-accel 0.4-1.1; they show about four seconds between the clang-accel preinstall line and the next package, but that is only a coarse log interval. For a valid comparison, use the same target, snapshot and cache conditions, record the exact accel RPM identity, time its unpack/install/postinstall separately, and also compare the complete buildroot setup interval up to the first Executing(%prep) line.

For QB 1226850, the BOLT begin report through completion of compare-root took 330 seconds, and the later post gate took 15 seconds. The largest recorded BOLT-scoped disk snapshot was 5,028,364,288 bytes. It includes BOLT work files, tool objects/libraries/executable and the positive ThinLTO-cache allocation delta; it is neither a continuously sampled peak nor total buildroot usage. The corresponding retained Toolchain run recorded 749 seconds, 24 seconds and 5,028,392,960 bytes, respectively. These are observations from separate environments, not a controlled timing comparison.
