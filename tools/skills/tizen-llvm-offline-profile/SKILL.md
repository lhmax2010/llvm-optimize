# Offline Tizen LLVM profile generation

Generate the IR profile and its paired BOLT profile on an authorized offline build host. Ship both compressed assets and their manifest in the source package. Quickbuild (QB) consumes the assets during the release build. Instrumentation and training run offline.

Regenerate after an LLVM version update, a change to source, recipe, toolchain inputs or ordered flags that affects Clang, or a failed build-time profile check. Qualify Toolchain (T) and Base-Dev (D) identities separately. A BOLT profile belongs to the exact relocated, debug-stripped binary on which it was trained. Verify identity before investigating match quality.

## Prepare an input set

- Use a Linux host with Python 3.11+, Git, GBS, a pinned Tizen repository snapshot with its build configuration, and isolated writable offline roots. Stage the RPM dependencies, model assets, matching sysroots and toolchain before disconnecting. Review historical measurements and per-stage admission in [resource-budget.md](references/resource-budget.md).
- Pin the LLVM commit containing the spec. Supply its full commit ID, project, snapshot label, project configuration and actual artifact paths in a copied [config.example.json](config.example.json). Each argv is an array, and its executable and working directory are absolute. Substitute the appropriate paths inside or outside the build root. Keep the pinned source checkout read-only and use two fresh local packaging copies or a reviewed site adapter.
- Stage all 23 training inputs, the ordered compiler arguments and their file identities. [training-set.md](references/training-set.md) explains the synthetic recipe, the preprocessed translation units, path placeholders and licensing. The JSON file can be replaced by an explicitly reviewed corpus with fresh identities.
- Use the pinned LLVM release for llvm-profdata, llvm-readelf, llvm-strip and Ninja. Obtain llvm-bolt, merge-fdata and the BOLT instrumentation runtime from the matching source and build configuration. Set the actual paths to the completed artifacts. For a private instrumented compiler, configure tool_launchers with its matching loader and library paths. Configure training_extra_args.ir with -fintegrated-cc1 for that launcher. See [compiler-launch.md](references/compiler-launch.md).

~~~sh
/usr/bin/python3 -B /path/to/skill/scripts/pgo_pair.py \
  --config /path/to/profile-config.json --output /path/to/jobs/profile-pair --dry-run
~~~

Dry-run prints argv, selected stages and budgets without launching a subprocess. Use --resume with the same configuration and output directory to rehash normal checkpoints. For an already linked instrumented compiler whose original attempt lacks a checkpoint, use --resume --recover-instrumented RECEIPT --stages ir-train with a fresh result directory. A recovery dry-run verifies the receipt and prints the training plan without writing a checkpoint. See [compiler-launch.md](references/compiler-launch.md).

## Eight stages

1. **instrumented-build.** Run the configured offline GBS commands in the instrumented packaging copy. Pass -DLLVM_BUILD_INSTRUMENTED=IR to CMake and build the instrumented Clang and profile runtime. Use the same project snapshot, target configuration and feature set as the intended PGO build. Deliver the instrumented Clang and the LLVM-version-matched llvm-profdata. Record source tree, spec and build configuration identities, actual CMake argv, versions, hashes and instrumentation warnings. Stop on build or tool-identity failure.
2. **ir-train.** Run the instrumented Clang once per training row using the row's ordered argv followed by -c INPUT -o OBJECT. Set LLVM_PROFILE_FILE to a separate directory for each row with a %m-%p.profraw filename. Verify each input hash before training. Expect one fresh nonempty profraw per row. Retain the argv, raw profiles, build/training warning counts and first warning. Stop on a failed compile or ambiguous/missing profile output.
3. **merge-profdata.** Run llvm-profdata merge -o CLANG.PROFDATA with the 23 inventoried profiles. Record the input and output hashes, version and merge log. An approved inspection may also run llvm-profdata show to verify the instrumentation level. Stop on missing inputs, merge failure or empty profdata.
4. **pgo-build.** Stage profdata in the offline packaging copy and expose it at the actual path visible to CMake. Build the shipping configuration with -DLLVM_PROFDATA_FILE=PATH and ordinary Clang, with the release BOLT rewrite deferred. Keep the expected ThinLTO/MLGO and hybrid-link settings. Exclude compiler-rt, OpenMP and other runtime targets from PGO in CMake. Use the source recipe's native archive conversion and normal installation to produce the shipping payload. The converter runs four workers with a 4 GiB per-process address-space limit. If a member compiler reports allocation failure, the recipe allows one serial retry at 8 GiB after the worker pool finishes. Preserve each ARCHIVE_MEMBER_RETRY line and the matching convert-retry.json receipt. Use its max_rss_kib to distinguish process address-space pressure from a build cgroup OOM. A failed retry fails the stage. Verify the main and any separate runtime Ninja graphs via ninja -t compdb -x and inspect commands for non-phony outputs it omits. Main C/C++ compile commands use exactly one -fprofile-instr-use=PATH. A link command may repeat that exact option once. Runtime commands, including compiler resource library outputs and compiler-rt or OpenMP sub-builds, carry no PGO flags. Read ninja-gate.json for the complete list of violations. Scan the resulting installed executables, shared libraries and every native static-devel archive member for instrumentation. Record the graph identity, audited payload root and gate result; PGO match stays UNKNOWN pending a validated method. Stop on a mismatch, missing graph or runtime dependency.
5. **bolt-tools-relink.** Configure BOLT in the matching PGO build tree, build llvm-bolt, merge-fdata and the matching instrumentation runtime. Use ninja -t commands -s bin/clang-22 to capture the exact original Clang link edge. Use the packaging helper's replay command (or a reviewed equivalent) to retain the original flags and objects and add --emit-relocs with a separate output and dependency path. Run that replay and llvm-strip --strip-debug to produce the BOLT input. Preserve the original compiler, relocation sections and link log. Verify relocation/debug-section handling and record tool, runtime and input hashes. Stop if the original edge, tools or relocations cannot be established.
6. **bolt-instrument-train-merge.** Run llvm-bolt with -instrument, --thread-count=1, -runtime-instrumentation-lib=PATH, -instrumentation-file=PREFIX, -instrumentation-file-append-pid and -instrumentation-binpath=PATH. Compile the same 23 inputs with the instrumented compiler and original ordered flags. Inventory exactly one fresh nonempty fdata per row, then run merge-fdata and capture its standard output. Record the executable, files, argv and merged fdata hashes. Stop on missing profiles, changed inputs or tool/merge failure.
7. **bolt-match.** Run the newly merged fdata against the exact input ELF from stage 5 using the release rewrite options shown by dry-run. Require a successful, trusted rewrite and -stale-threshold=5. Require both 100 × (S+U) ≤ 5 × (N+U) and 100 × S ≤ 5 × N. Persist N/M/S/U/Q and both ratios. infer-stale is forbidden. Fail closed on a truncated or malformed counter log, invalid counts or a nonzero return. Verify identity, retrain, or disable BOLT before proceeding. Keep the threshold fixed. See [gates.md](references/gates.md).
8. **write-manifest.** Write the two xz assets and llvm-profiles.manifest. Record hashes and sizes before and after compression, training argv and identities, tool versions and hashes, instrumentation warnings, the BOLT input and gates. Validate both T/D and switch-keyed mappings before integration. Generated manifests remain UNQUALIFIED until package acceptance. See [manifest-schema.md](references/manifest-schema.md).

## Bind the offline build to the packaging recipe

The example GBS commands are templates. In the instrumented packaging copy, add the IR CMake switch and preserve the compiler and its matching libraries in the offline root. In the PGO copy, add offline-clang.profdata as an offline-only Source, bind it to the CMake path in profile_path_in_build, keep the runtime exclusion, and defer the BOLT rewrite. This avoids requiring a BOLT profile during the build that produces its training binary. Remove the offline-only overlay from the release recipe. Retain GBS roots and expose their Ninja/payload paths in the config. Select the paths and context-specific wrapper commands from the actual GBS layout. Where compiler, relink, or runtime paths are inside a root, execute those commands in that same root or use a reviewed equivalent adapter.

For release integration, use conditional Source declarations for the compressed profiles and manifest, validate both compressed and uncompressed SHA-256 and sizes before use, and select one row by T/D identity and effective PGO/BOLT switches. Reject PLACEHOLDER, missing, or duplicate mappings. Keep clang_pgo off by default until acceptance. The llvm_speedup master switch controls PGO, hybrid linking and BOLT. When PGO is off, continue to use Source1200 if BOLT is on. Keep compiler-rt and OpenMP outside PGO and run the payload dependency check on each output mode. Perform package and object qualification before marking READY.

## Run safely and finish

With `resources.stage_admission` enabled, launch each selected stage in its own capped service. Reserve 4 GiB from MemAvailable and cap a heavy stage at 24 GiB. Full package builds require at least 10 GiB in the child cgroup. BOLT instrumentation, training and merge require at least 18 GiB and keep their existing serial command structure. See [resource-budget.md](references/resource-budget.md) for the other stage floors and thresholds.

For LLVM build stages, pass the Ninja limit as the `mlgo_build_jobs` RPM macro. Use `scripts/build_jobs.py install ROOT` in the prepared, private RPM root and pass its printed path through the `_buildshell` RPM macro. The wrapper adjusts the CMake compile and link pools and the lld ThinLTO worker count. It verifies the generated Ninja pools and cache before writing `LLVM_BUILD_JOBS`. Ensure the RPM build reuses the prepared root and inspect its log for the actual Ninja command. When configuring the BOLT tools on a retained graph, use `build_jobs.py reconfigure BUILD_DIRECTORY CMAKE` and capture the relink line after reconfiguring. The driver provides `PROFILE_JOBS`, `PROFILE_THINLTO_JOBS`, and `PROFILE_LINK_JOBS` for the selected stage. For a dry-run, supply `--memory-available-bytes` to display the planned counts and expanded commands.

Keep the 3 GiB memory and 15 GiB disk watchdogs active. The launch service may stop only its own current child service when a stop line is crossed. Configure build-tree cleanup only after all artifacts needed by later stages have been retained and hashed.

Use an isolated user service if systemd is available. Set MemoryMax to the approved tier, MemorySwapMax to 0, an approved CPUQuota and nice/IO priority. The service cgroup is an extra boundary for commands that move into independent process groups. An ordinary process has the controller's admission/watchdog but lacks hard cgroup memory/swap limits and cannot contain deliberately detached descendants. Use an ordinary process only on a dedicated host with equivalent approved containment. On OOM or external kill, capture the service journal, exit and last artifact in the final summary if the controller could not write it.

## Investigate common failures

- LLVM Profile Warning about exhausted value counters indicates incomplete recording of some values for that process. Separate build-time instrumented tools from training runs. Record the first warning and count, then check whether the affected process contributed a merged profraw. Do not infer BOLT staleness or an IR match rate from these warnings.
- When -use-old-text reports that the old text range is too small, preserve the warning, input/output identities and actual layout. Follow the package's layout and size gates. Changes to the release options require separate qualification.
- If Ninja still carries PGO options in runtime subprojects, inspect their actual compile edges and remove the inherited options in the local subproject scope before retrying. ldd cannot inspect archive members and must not substitute for ELF inspection.
- PGO match is UNKNOWN until the query-stage counting method passes fixture and real compiler checks. [pgo-match-method.md](references/pgo-match-method.md) describes the remaining validation.

On a host with a private target toolchain, use the optional tool_environment configuration object to assign loader variables by tool key. This keeps the target library search path out of Git and build-adapter commands. The special key bolt-instrumented-clang applies to the generated training executable.
