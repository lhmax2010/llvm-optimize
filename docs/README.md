# LLVM 工具链优化工作区产出规范

本工作区用于 Tizen 平台 LLVM 工具链执行吞吐优化。需要评审的产出提交至
<https://github.com/lhmax2010/llvm-optimize>。

1. **评审文档放在 `docs/`。** 报告、方案和设计文档采用编号前缀，便于排序，
   例如 `00_workspace_setup.md`、`10_xxx.md`。
2. **脚本放在 `tools/`。** 分析脚本和基准测试脚本随相应产出提交。
3. **中间产物放在 `temp/`，不提交。** 包括原始日志、临时数据和大文件；
   该目录仅提交 `.gitkeep` 以保留目录结构。
4. **每完成一个任务，提交并推送一次。** 提交信息使用简洁英文，说明本次
   产出是什么。提交前检查暂存文件清单、文件大小和忽略规则。
5. **不向 Gerrit 推送任何内容。** 所有代码改动都要等评审全部通过后，
   才会进入 Gerrit 流程；本工作线当前只推送上述 GitHub 仓库。
6. **超过 10 MB 的文件不进仓库。** 按 10 MB = 10,000,000 字节检查，
   将文件放在 `temp/`，并在相关文档中写明其工作区绝对路径。

目录职责：

| 路径 | 用途 | 是否提交 |
| --- | --- | --- |
| `docs/` | 需要评审的报告、方案和设计文档 | 是 |
| `tools/` | 分析脚本和基准测试脚本 | 是；空目录用 `.gitkeep` 保留 |
| `temp/` | 中间产物、原始日志和大文件 | 否；仅保留 `.gitkeep` |
| `llvm/` | 工作区已有的 LLVM 源码树 | 否 |
| `gbs_llvm.conf` | GBS 配置 | 是 |

`.gitignore` 按路径和文件名排除文件，不能自动按大小过滤。每次提交仍需
确认没有超过 10 MB 的文件进入暂存区。
