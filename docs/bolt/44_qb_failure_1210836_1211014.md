## 4. 与 hybrid / BOLT 的关系

| 检查对象 | 本次证据和结论 |
|---|---|
| hybrid 的链接方式 | 没有 cmake/ninja/link 或已产出工具运行记录，不能归因于 libLLVM/libclang-cpp 链接或 RUNPATH |
| BOLT tool-plan / tool-verify | 未执行；不是111+2白名单误拒 |
| profile / strip / tiny / real / 安全属性 / compare-root / post | 全部未执行；没有门禁数值可报告，不标 PASS |
| 其他依赖包失败 | 两轮 L5560 都是 `total_fail_pkgs: {}`，没有可列出的失败包；是项目仓库故障 |
| 同一源码的本地验证 | 39号完整构建及门禁通过，但使用不同依赖环境，不能代替本次QB验证 |

因此没有证据支持修补 `packaging/llvm.spec`、`packaging/clang-bolt-helper.py` 或 hybrid 的 CMake 改动来解决眼前故障，也没有理由关闭门禁。修复仓库后仍需验证三个架构，不能据本报告直接宣称 QB 通过。
