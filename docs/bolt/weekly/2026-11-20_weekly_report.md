# Tizen LLVM Toolchain Optimization - Weekly Report (Nov 16-20, 2026)

Nov 20, 2026 · @Hao

## Summary

Batch 1 (x86\_64 hybrid linking, BOLT-optimized clang, fixed flags and the static-archive converter) is functionally complete, and batch 2 (PGO+BOLT) produced its first PGO profile this week.

- **Batch 1:** the final code adds on/off switches for each optimization and a hardened BOLT build helper. Pre-merge builds pass on Tizen-Base-Toolchain and Tizen-Base-Dev for x86\_64, armv7l and aarch64, and all 102 binary packages match the previously validated build.
- **Batch 2:** PGO support is implemented behind a switch that is off by default. The first PGO profile (52.5 MB, from 23 training compile jobs) is generated; the PGO build and its paired BOLT profile come next.
- **Results so far:** BOLT makes clang compile in about 0.856x the time (historical local measurement); hybrid linking shrinks the LLVM file set used by qemu-accel by 77%; BOLT adds about 330 seconds to the x86\_64 package build.

## BOLT + PGO enabling steps

No profiling runs on QB: both profiles are generated offline from the same source and recipe, shipped xz-compressed in the source package with a manifest, and QB only uses them.

**Offline profile generation** (repeated only when a regeneration trigger fires)

1. Instrumented build: build llvm from the same source and spec recipe with IR instrumentation.
2. PGO training: run the instrumented clang on a fixed training set of 23 representative compile jobs from Tizen packages, with their exact compile flags.
3. Merge: llvm-profdata merges the raw profiles into one PGO profile.
4. PGO build: build llvm with the PGO profile (-fprofile-instr-use). compiler-rt and OpenMP runtimes are excluded from PGO.
5. BOLT tools and relink: build llvm-bolt and relink the PGO clang with relocations kept.
6. BOLT training: instrument the PGO clang with llvm-bolt, run the same 23 jobs, and merge the results with merge-fdata.
7. BOLT match check: the BOLT profile must match the PGO clang within the existing staleness limit (stale functions at most 5%).
8. Package: compress both profiles and write a manifest that binds them (source and recipe identity, training set, tool versions, SHA-256 and sizes). The two profiles are always replaced together.

Regeneration triggers: an LLVM version update, a source or recipe change that affects clang, or a QB build failing one of the profile checks below.

**QB build (profile use only)**

1. Before configure: check the manifest and the SHA-256 of both profiles, and that the build matches an identity the manifest certifies; otherwise the build fails.
2. Configure with LLVM\_PROFDATA\_FILE pointing to the PGO profile.
3. After configure: check that -fprofile-instr-use is applied to the LLVM, Clang and LLD targets and to no runtime library.
4. Normal build, including the static-archive conversion.
5. BOLT: relink clang with relocations and rewrite it with llvm-bolt using the paired BOLT profile; the 5% staleness limit applies as today.
6. Existing post-build checks: the BOLT-optimized clang must produce byte-identical objects to the ordinary clang on the test cases for armv7l, aarch64 and x86\_64; debug-link, debug-file and permission checks.
7. Profiling-runtime check: no shipped archive member, executable or shared library may contain \_*llvm\_prf*\* sections, \_*llvm\_profile*\* symbols or a libclang\_rt.profile dependency.

**Switches.** clang\_pgo (x86\_64 only) sits under the llvm\_speedup master switch next to hybrid\_link and clang\_bolt. It stays off by default until the PGO match check and the build-identity rules are validated. With PGO off, the build is the batch 1 build.
