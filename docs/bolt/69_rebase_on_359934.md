### 6.1 原因与修复范围

此前第 4 节的失败记录保持不变。本项只修本地 basedev 入口及其测试，不改 LLVM 源码、Toolchain 入口或历史根。

旧 log-restarts.jsonl 唯一一条为 time_ns=1793949050085331961、old_position=22121，即 2026-11-06T15:10:50.085332+08:00。原始日志 L6 的 build 起始时间为 Fri Nov 6 07:10:50 UTC 2026；L276 为 [265s] Executing(%prep)，L290 才是 [288s] Executing(%build)。phase-events.jsonl 的 ordinary-build 记录时间为 15:15:38。因此这次 restart 发生在完成独立 prep 后、正式 build 开始重写日志时，早于 %build/CMake，不是编译阶段日志倒退。采样器先读到了 22,121 字节旧 prep 日志。

对照 [62 §2](62_afternoon_20261105.md) 和 toolchain 副本，basedev 缺少：启动 build 服务前保存 prep_log_epoch（inode 与头 4096 字节）；日志轮询先等待新 epoch，再从位置 0 开始复制，旧 prep 字节不进入证据；演练模式资源报告读取自己的原始 .build.log。旧 resource_report.report() 无条件调用 canonical_log()，后者只查 gbs-driver/local/repos/*/x86_64/logs/success/llvm-*/log.txt；按设计停在 CMake 不会有成功包日志，所以抛 exactly one original successful GBS log required。

本次将 toolchain 的上述代码原样同步到 basedev；资源报告代码与 toolchain 逐字相同。另将已有 rehearsal-02 分支接到 launch.sh/selection 校验，以便用全新的 retry-02 根和独立服务名保留旧现场。未放宽 log-restarts=0、日志大小门禁、full 模式成功日志要求或任何发布门禁。SHA256SUMS 更新本次改动条目；新增 test_handoff_report.py。完整 [入口 diff](../../tools/bolt/results/rebase-359934-20261106/basedev-repair/entry.diff) 和修改前副本已保存。
