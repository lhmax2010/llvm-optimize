# Tizen x86_64 LLVM：BOLT+PGO 产品化、构建资源优化与其他提速方案 设计 v2

日期：2026-11-06
范围：Tizen-Base-Toolchain 与 Tizen-Base-Dev 中 x86_64 的 llvm 包。qemu-accel 从这个包取出 clang、lld、llvm-ar，用来交叉编译 armv7l/aarch64 包，所以这个包的执行速度直接决定平台包的编译速度。

基线：`sandbox/lhmax2025/bolt_pgo = 7d5e28ca89ed68e3360765bc4e42234eaaabae27`（tree `33d96ba16de757458e0a0cec5a2b89b2ef41a53f`）。

- 三个提交依次为：`a73a7da3`（混合链接）→ `e08ed9ed`（BOLT + debuglink）→ `7d5e28ca`（固定编译参数 + release 转换）。
- 它们改接在总部 Change 359934 的 patch set 10（`13c3e223`）及其父提交 357163（`cf4b6777`）之上。这两个 change 目前都是 NEW，tizen_base HEAD 仍为 `f999bd40`，风险见第 8 节。改接与演练结果见 69 号。
- 本文提到的"基线"一律指这个提交。63 号的完整构建数据取自改接前的 `9e39fa8a`；69 号第 2 节已证明，两者的 spec、BOLT helper 和六个 CMake 文件完全相同，只有转换器不同。所以 63 号的数据可以继续引用，但要注明测量所用的提交。

## 0. 目标、约束与验收口径

### 0.1 本月四项目标

1. 交付完整的 BOLT+PGO 实现，并给出编译速度提升数据。
2. 在不影响效果的前提下，降低编译 LLVM 本身所需的内存、磁盘和时长。
3. 代码上传前，必须经三家外部评审确认没有问题。外部评审是必经流程，但不能代替第 6 节的运行验证门槛。
4. 在静态链接、-O3、BOLT/PGO 之外，评估其他提速方案。

### 0.2 硬约束

沿用既有裁决：

- 不能导致其他包编译失败。
- 本地工作机只做功能和稳定性验证，不作为性能结论的来源。性能结论以 QB 为准，按内部的 A/A + A/B 交错协议判定。
- 本地验证必须与 QB 条件一致：同一快照、同一 build.conf、同一仓库。

内存分三类，分别报告、分别裁决，不混用，也不用一类的改善去抵消另一类的回归：

| 类别 | 指什么 | 规则 |
|---|---|---|
| 第一类 | 构建 llvm 包本身的资源 | 显著增加时，必须在试验前报备，并先在 QB 上验证 |
| 第二类 | 用安装后的 clang/lld 编译其他包时的资源 | 可接受的变化幅度待裁决（第 7 节） |
| 第三类 | 其他包产物在运行时的性能与内存 | 不得回归（硬约束） |

### 0.3 "效果不变"的两套口径

按比较对象分两套口径，比较器把口径作为必填参数，没有默认值。

**口径 A：本地对本地**（同提交、同快照、同 Release、同 find-debuginfo 并发度）。第 4 节的全部验证使用这一套。

- 已安装 RPM payload 的以下各项与基线完全相同：文件集合、路径、类型、mode/uid/gid、符号链接目标、硬链接关系、文件内容；自动生成的 Provides/Requires；RPM 脚本。
- 允许的例外只有两类：
  - 记录节：.GCC.command.line、.llvmcmd、.comment。差异必须单列，并归因到本次批准的参数或路径变化，不能当作任意差异的豁免。
  - 归档成员头的日期字段：沿用 37 号第 10.1 节已裁决的三个条件，即成员名单与顺序一致、逐成员内容 SHA 一致、屏蔽日期字段后全字节一致。
- 不允许 debuglink CRC 差异，也不允许 .debug_line 长度字段、DW_AT_comp_dir 的差异。这几类只来自本地与 QB 的 Release 号不同，在同口径的本地对照里不会出现，放进允许清单只会掩盖真实回归。

**口径 B：本地对 QB。** 第 2.5 节的身份核对、第 3 节的版本身份使用这一套。

- 包含口径 A 的全部要求。
- 另加 67 号第 8.1 节已裁决并启用的三条规则：.debug_line 逐单元长度增量、DW_AT_comp_dir 等长加 POSIX 词法等价、debuglink CRC（先验证配对的符号文件，再验证文件名、实际 CRC 和其余 ELF 内容）。
- 按这一套，23 个包中 21 个 PASS。llvm 源码包和 debugsource 包的剩余差异如何处理，是第 7 节的裁决项；裁决前继续判 FAIL。

两套口径都不覆盖 RPM 文件本身的字节（压缩方式、头部时间戳）。凡是改动 RPM 压缩方式的方案，都单列为裁决项，默认不做。调试信息格式的改变（压缩调试节、split DWARF、DWARF 版本）属于效果改变，不在本设计范围内。

## 2. BOLT+PGO 产品化

### 2.1 候选方案

| 方案 | 构建内做什么 | 构建时间 | 资源 | 主要代价 |
|---|---|---|---|---|
| 甲：构建内完整 PGO | 插桩构建 → 训练 → 合并 → 带 profile 正式构建 → BOLT 插桩、训练、优化 | 约 +81 分钟（≈ +47%，按 58、59 号的实测值相加） | 单进程峰值 VmHWM 17.0e9 B（BOLT 插桩）；磁盘已知部分规划下界约 92–96 GiB，加 30 GiB 保留线后为 122–126 GiB（59 号第 3、7 节），真实峰值未测 | 时间和磁盘最大；需要在构建内新增 merge-fdata、插桩 runtime，以及训练输入作为源文件 |
| 乙一：两份 profile 都预采集，离线成对生成（推荐） | 带 PGO profile 正式构建 → 用预采集的 BOLT profile 做 rewrite（与现状相同） | 只增加"带 profile 编译"的开销，待实测 | 待实测；预期接近现状 | 两份 profile 必须与构建输入严格对应；输入一变，就要离线重新生成或重新认证 |
| 乙二：PGO profile 预采集，BOLT profile 在构建内采集 | 带 profile 正式构建 → 构建内 BOLT 插桩、训练、合并、优化 | 在乙一基础上再 +461 s（实测） | 单进程峰值 VmHWM 17.0e9 B；临时磁盘约 +3.8 GB（插桩 clang 0.58 GB + 原始 fdata 3.0 GB + 合并结果 0.19 GB） | 改动已通过评审的 BOLT 流程：新增两个 ninja 目标，重新认证 111+2 任务白名单，替换 profile SHA 门禁；23 份训练输入及其完整编译参数要作为源文件发布 |

推荐乙一，理由如下：

- 它是现状的最小扩展。现在的 BOLT profile 已经是预采集、随源码发布的，乙一只是把 PGO profile 用同一套机制一起发布。
- BOLT 部分的 111+2 任务白名单、profile 匹配门禁（-stale-threshold=5，R 和 S/N 都不超过 5%）、rewrite 参数和各级门禁都不用改，此前的评审结论继续有效。
- 体积可接受。合并后的 BOLT profile 约 194 MB，按现有 Source1200 的压缩比看，压缩后预计在 10–20 MB 量级；PGO profdata 52.5 MB，压缩后的大小待测。

乙一能成立，是因为基线是自托管构建（用快照里的上一版 clang 编译 llvm 包），并且 63 号已经实证：同一提交、同一快照下，本地与 QB 的 clang 逐字节相同。只要 PGO profile 和构建输入固定，构建出的 PGO clang 就是确定的，离线采集的 BOLT profile 就能对上。为了保证这一点，必须加第 2.2 节的输入身份硬检查。

乙二和甲都保留为备选，不作为默认方案。

### 2.2 乙一的具体设计

**离线生成**（独立脚本，不在 RPM 构建内运行）

- 在与 QB 相同快照的 gbs 根里，按甲的流程一次完成以下步骤：
  1. 构建插桩 clang；
  2. PGO 训练，合并得到 llvm.profdata；
  3. 用这份 profdata 构建正式的 PGO clang；
  4. 在这个 PGO clang 上做 BOLT 插桩、训练、合并，得到 BOLT profile。
- 两份 profile 和一份共同清单 `llvm-profiles.manifest` 在同一次运行中产生，不能分开替换。
- 清单记录：
  - 输入身份（定义见下）；
  - spec 提交与 tree；
  - 快照名与 build.conf SHA；
  - 插桩参数，包括 `-mllvm -vp-counters-per-site` 的取值；
  - PGO 与 BOLT 两份训练清单（含 SHA 和完整编译参数）；
  - llvm-profdata、llvm-bolt、merge-fdata 的版本与 SHA；
  - 插桩运行期间 `LLVM Profile Warning` 的条数与首行原文；
  - 两份 profile 的 SHA 与大小（压缩前、压缩后）；
  - BOLT 匹配结果（N/M/S/U/Q、R、S/N）。
- 计数器耗尽：58 号的插桩构建出现了 830 条"静态计数器耗尽"警告，说明间接调用的 value profiling 不完整。本月先用加大的 `-vp-counters-per-site` 重新生成一次，比较两份 profile 的间接调用记录数与警告条数。收益不明显的话，就把这条作为已知限制写进清单，不留空白。
- 训练集要求：
  - 在采集前冻结；
  - 覆盖 armv7l 与 aarch64，并评估 x86_64 是否需要覆盖；
  - C 和 C++ 都有，取自真实 Tizen 包；
  - 列出目标、语言、优化等级的覆盖矩阵；
  - 与第 3 节的测速集按源文件隔离，不只按内容 SHA 隔离（第 3.1 节）。
  - 现有 BOLT 的 23 份训练输入（13 份 ARM + 10 份 AArch64，其中 3 份是合成文件）只能作为初始资产，未经审计不能声称代表全平台负载。

**输入身份**：只取会影响 profile 匹配的输入，与无关的打包改动解耦。

1. 源码内容摘要：解包并打完补丁后的源码目录，不含 packaging/ 下与编译无关的文件。按路径排序，对内容计算摘要，在 %prep 中求得。
2. 固定编译参数串，以及影响代码生成的 CMake 选项。
3. 构建所用编译器（快照里的 clang）的版本串，以及它对应的 LLVM 源码身份。不用编译器二进制的 SHA，因为 PGO/BOLT 不改变编译器的输出，用二进制 SHA 会让每次发布都误判失效。这一点由第 2.5 节的身份一致性验收支撑。

**spec 中的使用**

- 新增 Source：两份 profile 和共同清单。
- %prep 中做三项检查：
  - 两份 profile 的 SHA 与清单一致，否则构建失败。
  - 当前的输入身份必须出现在清单的认证列表中，否则构建失败，并打印双方的身份值。
  - 清单可以记录多个已认证的身份。输入变化时，可以先做离线兼容性复验（BOLT 匹配门禁通过，PGO 诊断计数已记录），通过后追加认证，不一定要重新训练。
- 通过 LLVM 自带的 CMake 选项 LLVM_PROFDATA_FILE 传入 PGO profile。上游 CMake 在文件不存在时只打 warning，所以 spec 要自己检查文件存在，并在构建日志中确认实际的编译命令带有 -fprofile-instr-use，否则失败。
- PGO 诊断只作观察，不作放行依据：
  - 分别记录 missing、hash mismatch 等可取得的计数。
  - LLVM 22.1.8 中部分警告默认关闭或被抑制，条数既不是完整的不匹配数，也给不出可靠的分母，因此不输出"过期比例"，不设比例阈值。
  - 未实现并验证完整分母之前，相关项一律记为 UNKNOWN。
- BOLT 侧继续沿用 -stale-threshold=5，以及 helper 的 R、S/N 都不超过 5% 的硬门禁，不放宽。
- 开关：PGO 和 BOLT 分别有 %bcond 开关，默认都开启。
  - 关闭 PGO 时，行为与当前基线完全相同（包括总部转换器的改动），不回退到旧的源码链。
  - 训练或匹配失败时明确报错，不在构建中静默降级；需要回退时，靠提交修改开关实现。

**PGO 的作用范围**：LLVM_PROFDATA_FILE 加在整个 CMake 构建的全局编译参数上，不是只给 clang 用的。实施前，必须先从构建日志中盘点所有带 -fprofile-instr-use 的编译单元及其所属目标，并公开清单。处理规则：

- **主构建中的 LLVM/Clang/LLD 库和工具：** 允许在作用范围内，属于预期行为。lld、llvm-ar 不单独训练，但它们的代码同样会变，要按第 2.5 节验收。
- **compiler-rt、libomp 等随包发布、会被其他包链接的运行库：** 本期排除在 PGO 作用范围之外。若盘点发现它们已在范围内，先用 CMake 隔离；隔离不了的，列为裁决项，并补充 ABI、功能和下游运行性能/内存验收。
- **静态库转换器：** 成员的 recorded command 会多出 -fprofile-instr-use 等参数。转换器必须给它们明确分类：分支权重和入口计数已写在 IR 中，因此不重放。不能笼统忽略所有 profile 参数，未知参数照旧拒绝。这项改动要用真实的 PGO bitcode 成员做转换验证，并验证 GNU ld 与 lld 两类 static-devel 消费者。
- **llvm-static-devel：** 归档成员的代码会随 PGO 变化。这一点单独列在变更说明里。

**-use-old-text 放不下时的处理**（缺口 686,688 B，占可用 .text 的 0.85%）

- 现有参数已经包含 -split-functions、-split-all-cold、-split-eh，这些不是还能新加的手段。
- 候选手段，合成一个实验批次一起测，因为它们会互相影响基线：
  1. 允许改用新段（现状行为）。记录"需要 / 可用"、最终 strip / RUNPATH / debuglink 处理后的文件大小、LOAD 映射和运行时 RSS。参考数据：非 PGO 口径下不用旧段时，体积为 +16.75%（37 号第 10 节）；PGO 口径还没有打包后的数字，本月先补这一项。
  2. 在普通 clang 的链接上加 -Wl,--icf=safe，在 BOLT 之前缩小 .text（第 5 节）。
  3. BOLT 侧还没用过的手段：--split-strategy=cdsplit，以及旧段内的对齐值。警告原文写的是"using 0x200000 alignment"，控制它的具体选项名要先用 `llvm-bolt --help-hidden` 核实。
  4. 显式关闭 -use-old-text，作为对照组。
- 不论走哪条路径，产物都必须通过与旧段路径相同的全部正确性、安全属性、符号化和打包门禁，不能只凭退出码 0 判定可以发布。新增或变化的 BOLT 警告必须归因。
- 每组都记录 strip 后大小与 R、S/N。数据齐了再裁决（第 7 节）。在此之前，暂按"允许新段，同时打印数据"运行，不让构建失败。

### 2.3 范围扩展（第二阶段）

- lld 是否单独做 PGO/BOLT，要等第 4.1 节把 ThinLTO 大链接从普通编译阶段拆出来之后再判断。如果要做，训练负载必须包含链接任务；现有训练全是编译任务，profile 会偏向编译路径。
- llvm-ar 不在静态库转换的关键路径上。转换器重新打包用的是 /usr/bin/ar，逐成员编译用的是 clang。所以本月不为 llvm-ar 单独做 PGO/BOLT。
- 本月只为 clang 交付 PGO+BOLT。lld、llvm-ar 只给可行性和资源数据。

### 2.4 资源报备

报备在大资源试验之前提交，先按历史测量值和不确定性给出预算，试验后再补实测。每个数都标明口径：

1. **cgroup memory.peak（含文件缓存）：** 历史 PGO 试验的正式编译阶段为 20.21 GiB（58 号），当前完整构建为 17.26 GiB（63 号）。两次的 Ninja -j 和 MemoryMax 相同，但源码和快照不同，差出的约 3 GiB 只用于风险预报，不是受控条件下的 PGO 增量。
2. **不含文件缓存的部分：** 用 memory.stat 的 anon、file 两项分开。现有证据里没有这一项，在下一次完整构建时采集。
3. **最大单进程 VmHWM 及其完整命令行：** 乙一预计仍是 ld.lld，历史值 13.3e9 B。若选乙二或甲，最大单进程会变成 llvm-bolt -instrument 的 17.0e9 B，必须单独报备。

磁盘和时长待第一批实测。周报只列实测的时长、内存和磁盘，并标注口径。

### 2.5 正确性验收

**编译器身份一致性**：同一源码、配方、工具链、resource-dir 和 sysroot 下，比较 PGO 开/关 × BOLT 开/关四种组合。比较三项：目标文件字节、退出码、stderr 原文，要求全部相同。

输入分四类，在验收前冻结清单：

1. 现有 90 份 LLVM C++ 输入（20 个源文件 × 3 个目标，60 个唯一内容 SHA；67 号已恢复）。
2. 新增至少 30 份真实 Tizen 包的 C 预处理输入，其中多数小于 1 MB，覆盖三个目标。
3. 从一次真实构建的静态库转换中，取 100 个 bitcode 成员，按 recorded command 原样重放 `-x ir -O3`，比较输出。这条路径的产物会进入 llvm-static-devel。
4. 多种优化等级和语言标准的小样本（-O0/-O1/-O2/-Os/-O3，c11/c++17/c++20），另加未预处理的源码输入（覆盖预处理与头文件搜索），以及汇编输入。

**链接路径**：

- 用一个真实 C/C++ 包，在四种组合下各完成一次编译加链接，比较最终 ELF：除记录节和 build-id 外，逐字节相同。
- lld、llvm-ar 在 PGO 作用范围内，因此用固定输入分别验收 lld 的链接输出和 llvm-ar 的归档输出。

**原则**：

- "PGO/BOLT 不改变编译器输出"是待验证的要求，不是前提。任何不一致都按缺陷处理，先阻断，再定位到具体的优化或改写，不能以"差异很小"放行。
- 这项检查是很强的筛选，但不代表覆盖所有编译路径。

**先验证方法本身**：这套验收至今没有完整跑过（63 号 0/90，67 号恢复输入后也没有重跑）。第一批先用现有的两个版本跑通一次：

- V1b：基线以 --without clang_bolt 构建；
- V2：基线本身。

方法可用之后，再用于 PGO 版本。

**BOLT 改写警告专项**：解释两处"jump past end → nop"警告：

- 被换成 nop 的跳转是否可达；
- 它们落在函数的哪一部分；
- 现状发货的非 PGO BOLT 日志里是否也有同样的警告。

另外，针对这两个函数补定向输入（aarch64 上的分支密集代码、x86_64 上能触发 LEA 三地址转换的代码），比较 BOLT 前后的输出。1551 条 relocation 分析警告也要归因。

**可复现性**：

- 用同一份清单、在两个独立的干净构建根中构建，比较最终 ELF 和 RPM payload，按口径 A 判定。
- 离线生成本身不承诺可复现：profile 一旦固定，就以 SHA 钉住。但要记录两次生成之间的差异，作为维护参考。

**其余验收**：

- 本地 T/D 两个配置完整构建；
- install/LLDB 21 项检查；
- 安全属性、debuglink 与符号化检查；
- accel 实物验证；
- QB 两个项目全部架构通过。

## 3. 测速方法

### 3.1 本地（只给方向，不作结论）

**测速集**：采集 profile 前，冻结训练集与测速集。隔离同时按内容 SHA 和原始源文件检查；同一源文件的不同目标、参数或预处理版本归为同一组，不能分散在训练和测速两侧。

已核实的现状：

- 现有 BOLT 训练集与 90 份测速输入的内容 SHA 交集为 0。
- 但源文件交集是 10 个：BOLT 训练用的 10 个 LLVM 源文件全部在测速集里。

因此测速集分三层，分别报告，不合并成一个总比值：

| 层 | 内容 | 用途 |
|---|---|---|
| 第一层 | 训练过的 10 个源文件 × 3 个目标（30 条） | 只用来观察 profile 是否生效，不作为速度结论 |
| 第二层 | 未训练的另外 10 个 LLVM 源文件 × 3 个目标（30 条） | 同项目留出集 |
| 第三层 | 新采集的真实 Tizen 包预处理输入，至少 30 条，C 与 C++ 各半，分布在三个目标上 | 用于判断"平台包编译是否变快" |

- 第二、三层与 PGO、BOLT 两份训练集在源文件层面也必须不相交。
- 重复内容只保留一份参与计权，统计时按源文件分组处理相关性。
- 三层清单、来源包名、SHA，以及与训练集的交集表，作为测速报告的固定附件，每次测速都重新生成。

**启动开销**：空 C 文件和空 C++ 文件，各执行 -fsyntax-only 1,000 次，记录 user+sys 总和。BOLT 版 clang 比普通版大 9.0%，若退回新段会更大，所以启动与映射开销必须单独量化，否则在大 TU 上看不出来。这一项也用于给第 5 节的几项排序。

**版本**：V1b–V4 都从同一认证基线构建，只改变开关：

| 版本 | 内容 |
|---|---|
| V0 | tizen_base 当前 HEAD 的 GCC 编译版（f999bd40 的 QB 产物）。作为总部现状的产品参考单列，不用于分离 PGO/BOLT 的因果收益 |
| V1b | 基线，关闭 BOLT |
| V2 | 基线 |
| V3 | 基线 + PGO，关闭 BOLT |
| V4 | 基线 + PGO + BOLT |

报告 V2/V1b（BOLT）、V3/V1b（PGO）、V4/V3（在 PGO 上叠加 BOLT）、V4/V0（相对总部现状的总收益）。

**二进制形态**：一律使用打包安装后的二进制，即 strip 过、带 debuglink 的版本，不使用构建树中的中间产物。每个版本记录所用二进制的路径、大小和 SHA，并与 RPM payload 核对。

**执行**：

- 每轮的版本顺序，用测量前固定种子的平衡随机顺序，或轮换起点，避免某个版本长期排在固定位置。
- 加入同一编译器的 A/A 对照。
- 每个版本的首轮作为预热，弃用。
- 每份 TU 在固定 CPU 上串行编译，用 /usr/bin/time -v 记录 user+sys、wall 和最大 RSS。
- 每轮开始前记录 load average。超过 1 时最多等待 10 分钟，仍然超过的，把该轮标记为"有干扰"并从统计中剔除，剔除的轮次单独列出。剔除规则在测量前固定，不根据快慢事后删除。
- 轮数不预先写死：先跑 3 轮，估计每份 TU 的变异系数，再按"分辨 3% 差异、双侧 95%、power 0.8"算出所需轮数并补齐，算式写进报告。

**统计**：

- 主指标为逐 TU 配对比值的几何均值，置信区间用按源文件分组的 bootstrap，不用"每轮总和的中位数"。
- user+sys 和 wall 都报告。
- 只有 A/A 稳定、各轮方向一致时，才给出方向判断；否则写"数据不足以分辨"，这是合法结论。
- 同时报告三类内存中的第二类（编译时的最大 RSS）。

**包体积**：各版本 clang 二进制和 llvm 主包的安装大小。

### 3.2 QB（结论来源）

- 按内部 A/A + A/B 交错协议执行。设计里引用该协议的固定版本，避免测量之后再改判据。
- 本设计只提供可直接提交 QB 的分支，以及每个版本的产物 SHA。
- 首选负载是 Chromium（使用平台 clang），另取若干以 C/C++ 为主的 Base 包作补充。

**本期不做的：**

- 转换成员去重。转换参数含 -frecord-gcc-switches，输出路径会写进 .GCC.command.line，复用的产物无法与现行输出逐字节相同。要做的话，必须先定义缓存键（输入内容、完整后端参数、工具身份、路径上下文），并把记录节的归一化作为效果变化单独裁决。

- 压缩调试节、split DWARF、改用 DWARF 5、降低 -O 等级、减少调试信息。都会改变产物或效果。

## 5. 其他提速方案评估

下表是探索顺序，不是已测收益的排名。先确认热点和适用条件，再决定是否实现；没有本项目证据的收益一律记为"待实测"。启动开销基准（第 3.1 节）在原型之前先做，作为排序依据。

| 方案 | 原理 | 前提与风险 | 本月目标 |
|---|---|---|---|
| 链接期相同代码折叠（-Wl,--icf=safe） | LLVM 模板实例化多，代码相同的函数可以折叠，.text 变小 | 不用 =all，它会破坏"不同函数地址必须可区分"的假设。会改变普通 clang，与 -use-old-text、BOLT 重链复用、大页合成一个实验批次 | 本地原型：.text 大小，-use-old-text 能否用回旧段，三层 TU 的时间与 RSS，四种组合的身份一致性，函数地址可区分性抽查 |
| clang 驱动与 cc1 同进程 | 每次编译只映射一次 clang | LLVM 10 起默认在进程内运行 cc1（CLANG_SPAWN_CC1 默认 OFF），预计已经生效。先读构建根 CMakeCache，并用 strace -f -e trace=execve 核实；已生效则关闭此项 | 只做核实 |
| 替换内存分配器（在 clang、lld、llvm-ar 的链接中静态链入 mimalloc 等） | 编译器有大量小对象分配 | 依赖性质是构建期依赖（开发包与静态库），不是运行期 Base 包。LLVM 在 Linux 上没有对应的 CMake 开关，要改三个驱动的链接行。原型之前，先确认 Tizen 是否有对应包、glibc 兼容性和许可（mimalloc 为 MIT）。可能提高第二类内存；分配地址变化可能触发"指针顺序影响输出"的问题，必须做身份一致性验收 | 先做可用性与合规检查，通过后再做本地原型 |
| 代码段大页（BOLT -hugify） | 降低 clang 大代码段的地址转换开销 | -hugify 在启动时调用 madvise，内核不支持时失败即继续，不会报错；但要测的是有没有收益。0x200000 对齐会加重 -use-old-text 的容量缺口，所以与第 2.2 节一起裁决。没有 iTLB 计数之前，不预设收益 | 本地原型：本机 THP 分别设为 always 和 madvise 测上限；分别验证对齐、大页实际是否生效、RSS/PSS、冷启动 |
| perf 采样驱动优化（AutoFDO/Propeller） | 用真实负载上的采样 profile | 需要硬件 LBR 和权限；QB 上不能采样，不等于不能离线采集，但要证明离线负载与部署条件相符。收益待测 | 只做可行性调研，列入后续计划 |
| 静态 clang 的全程序去虚拟化 | 减少虚调用 | 可能破坏 clang 插件接口，正确性风险较高 | 只做可行性调研 |
| -fno-plt、-Bsymbolic-functions 等动态链接优化 | 减少 PLT/GOT 与符号抢占开销 | 对本设计的价值路径收益很小，因为 qemu-accel 取出的 clang、lld、llvm-ar 已是静态链接。但其余二十多个工具，以及 libLLVM.so、libclang-cpp.so 的使用者，仍然走共享库；-Bsymbolic 还涉及符号抢占语义和插件兼容性。以后优化那些工具时需要重新评估 | 不做，记录理由与适用边界 |
| 提高 -march 等级 | 使用更新的指令集 | QB 构建机 CPU 未知，可能 SIGILL；与"沿用项目 -march"的裁决冲突 | 不做 |
| 平台包默认使用 lld | 缩短包的链接时间 | 在单独的工作线中跟进 | 不在本设计内 |

## 7. 需要裁决的事项

1. **BOLT profile 的交付方式：** 推荐乙一，即两份 profile 都预采集、离线成对生成。备选是乙二（BOLT 改为构建内采集），实测代价为 +461 s、单进程峰值 VmHWM 17.0e9 B、临时磁盘 +3.8 GB，还要重新认证任务白名单和 profile 门禁，并把训练输入作为源文件发布。
2. **PGO profile 的交付方式：** 推荐预采集文件随源码发布。构建内完整训练（甲）只作为默认关闭的开关。
3. **输入身份不在清单的认证列表中时：** 推荐构建失败；离线复验通过后可追加认证，不强制重新训练。
4. **-use-old-text 放不下时：** 推荐暂时允许新段并打印数据，等第 2.2 节的实验批次结果出来再定最终做法；新段路径必须通过全部门禁。体积增量的可接受上限也需要确定。
5. **身份一致性验收失败时：** 推荐一律按缺陷处理，定位原因之前不放行。
6. **PGO 作用范围：** 运行库本期排除在外；llvm-static-devel 成员随 PGO 变化，是否接受。
7. **第二类内存**（编译其他包时编译器的内存）可接受的变化幅度与报备标准。
8. **llvm 源码包和 debugsource 包与 QB 的剩余差异**（17 个文件的权限 0664 对 0644、QB 写入 spec 的 VCS/Release/%patch 写法、debugsource 的 Release 路径前缀）：是定义为限定范围的已知环境差异单列显示，还是继续判 FAIL。
9. **"效果不变"** 按第 0.3 节的两套口径执行；RPM 压缩方式的改动需要另行批准。
10. **分配器方案若有收益：** 能否接受新增一个构建期依赖。

## 8. 风险

- **基线依赖两个尚未合入的总部 change：** 359934（patch set 10，NEW）和 357163（NEW），tizen_base HEAD 仍是 `f999bd40`（回退为 GCC 编译）。任何一个改版或不合入，三个提交都要重新改接；V0 与 V1b–V4 之间"用 clang 编译 LLVM 加 ThinLTO"这一差异的归属也会变。
- **BOLT 的 nop 改写还没有解释：** 两个后端函数中的"jump past end → nop"位于交叉编译 ARM/AArch64 的后端路径上，另有 1551 条 relocation 分析失败。本月必须给出解释并补定向验证（第 2.5 节）。
- **PGO profile 不完整：** 插桩构建时有 830 条计数器耗尽警告，间接调用的 value profiling 不完整，可能削弱 PGO 收益。
- **速度收益可能比预期小：** 目前只有噪声很大、而且是在训练集上测的本地数据。分层测速后，平台包那一层的收益可能明显小于 LLVM 源码那一层。最终以 QB 数据为准。
- **profile 随源码发布可能被质疑：** 52.5 MB 的 PGO profile 加上 BOLT profile 放进源码包，总部可能有顾虑。备选是甲，代价是构建时间约 +47%，磁盘规划下界 122–126 GiB。
- **"理论上不改变产物"的项可能证不出来：** 并行度调整、BOLT 重链复用、相同代码折叠，理论上不改变产物，但必须逐字节实证，实证不通过就放弃该项。
- **QB 构建机的内存和磁盘上限未知：** 每项改动都只报实测值，不作"可以接受"的判断。

## 9. v2 修订说明

- 更正 v1 对现状的错误描述：当前 BOLT 是"预采集 profile + 构建内 rewrite"，构建内不插桩、不训练。推荐方案因此改为两份 profile 都预采集（乙一）。
- 更正 v1 否决方案时用错的数字：3.0 GB 是 23 份原始 fdata 之和，合并后是 194 MB。
- 删除 v1 中基于警告条数的"过期比例 10%"，改为输入身份硬检查加多身份认证；PGO 诊断只作观察。
- 新增 PGO 作用范围盘点，以及转换器对 PGO 参数的分类。
- 更正 -use-old-text 的选项二（拆分参数已经在用），改为合并实验批次，并要求新段路径通过全部门禁。
- 身份一致性验收扩展为四类输入、三项比较，加上链接路径，并要求先用现有版本跑通一次；新增 BOLT 改写警告专项。

- "效果不变"拆分为本地对本地、本地对 QB 两套口径；新增归档日期例外和包元数据比较。
- 内存拆分为三类分别裁决。
- 资源候选按实测阶段占比重写：新增并行度调参和 BOLT 重链复用；删除不存在的自举阶段，以及已有的链接 job pool；转换去重移出本期；更正各项的现状事实。
